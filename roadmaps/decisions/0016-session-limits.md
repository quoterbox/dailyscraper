# 0016. Общий механизм лимитов сессий

Статус: принято (2026-10-28), уточняет [0013](0013-scaling-and-replaceable-backends.md)

## Контекст

Ограничений одновременных браузерных сессий много, и они комбинируются:
браузеры на машину, потоки на парсер, браузеры на одну прокси для одного сайта,
сессии на прокси у провайдера, отдельные лимиты для конкретных сайтов. Отдельная
проверка под каждый случай в `BrowserManager` растёт с каждым новым требованием и
не работает между запусками и машинами.

## Решение

- **Сессия описывается измерениями**: `host`, `site`, `proxy`, `scraper`, `run`,
  `project`, `kind` (`browser`, позже `http`). `site` — домен из `website`
  пакета, общий для всех его парсеров; без прокси `proxy` = `direct`.
- **Правило лимита** — набор измерений (`scope`), число (`limit`) и условие
  (`match`): не больше `limit` сессий на каждое сочетание значений `scope` среди
  сессий, подходящих под `match`. Сессия должна уложиться во все подходящие
  правила.
- **Переопределения**: правила с одним именем — один лимит; из подходящих
  действует правило с наибольшим числом условий, из равных — последнее. Поэтому
  сайту можно задать и больший, и меньший лимит, чем по умолчанию, а правило из
  настроек заменяет встроенное с тем же именем.
- **Встроенные правила** собираются из привычных настроек: `host_browsers`
  (`host`, `kind=browser`) из `max_slots`; `scraper_parallel` (`scraper`) из
  `max_parallel` с переопределениями из `scrapers.json`; `site_proxy`
  (`site`, `proxy`) из `max_browsers_per_site_proxy`, **по умолчанию 1**: один
  браузер на сайт через одну прокси, и через прямое подключение тоже. Больше —
  только явной настройкой. Остальные правила задаются списком `runtime.limits`.
- **Счётчики — leases в общем хранилище**: ключ «имя правила + значения
  измерений», TTL с продлением. Слот берёт места во всех своих ключах одной
  транзакцией или не берёт ни одного; ключи общие для всех запусков и машин,
  использующих хранилище.
- Бюджет памяти остаётся локальной проверкой машины, а не лимитом.

```json
{
    "runtime": {
        "limits": [
            {"name": "site_proxy", "scope": ["site", "proxy"], "limit": 3, "match": {"site": "dailyscraper.com"}},
            {"name": "proxy_sessions", "scope": ["proxy"], "limit": 5},
            {"name": "site_total", "scope": ["site"], "limit": 10, "match": {"site": "ozon.ru"}}
        ]
    }
}
```

## Последствия

- Новое ограничение — запись в настройках, а не код в `BrowserManager`.
- На этапе прокси `Allocator` выбирает прокси с учётом заблокированных ключей
  (`leases.blocked`), а режим изоляции `persistent` добавляет правило
  `(site, proxy)` с лимитом 1: постоянный профиль может открыть только один
  браузер.
- `max_parallel` парсера теперь общий для всех запусков на хранилище, а не для
  одного запуска.
- Без прокси сайт обрабатывается одним браузером, пока лимит связки не поднят:
  параллельность по одному сайту даёт число прокси.
- При переходе на Redis или PostgreSQL меняется только реализация `leases`.

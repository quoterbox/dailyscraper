# 0004. Ветки `dev`/`master`, git ведёт владелец

Статус: принято (2026-10-22)

## Решение

- Работа идёт в `dev`.
- В `master` сливается только завершённый этап: выполнены критерии готовности из
  [plan.md](../plan.md), тесты зелёные. На слиянии ставится тег (`v0.0.1`, …).
- Короткая ветка от `dev` — только для рискованных экспериментов.
- Все операции git (stage, commit, ветки, merge, push, теги) выполняет владелец
  проекта. Ассистент только читает состояние git (`status`, `log`, `diff`) и по
  готовности шага перечисляет файлы и предлагает сообщение коммита.

## Последствия

- `master` всегда соответствует последнему завершённому этапу.
- [status.md](../status.md) отражает состояние `dev`.

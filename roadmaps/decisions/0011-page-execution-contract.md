# 0011. Контракт исполнения страниц

Статус: принято (2026-10-23), уточняет [0009](0009-scraper-actions-hooks.md)

## Контекст

На этапе 2 логика страниц работает в одном процессе с одним браузером. Тот же
код потом будет выполняться внутри процесса-слота, поэтому его границы нужно
зафиксировать до появления слотов и очереди.

## Решение

- **Транспорт.** Пакет и исполнители видят `BrowserPage` (открытие с итогом
  `Navigation`, перезагрузка, текст, заголовок, прокрутка) и `ElementFinder`.
  Объекты Playwright наружу не отдаются; для hooks, которым нужен полный API
  (перехват ответов, сложные сценарии), есть явный `BrowserPage.playwright_page`.
- **Поиск элементов.** Альтернативы селектора опрашиваются по порядку с одним
  общим ожиданием: `wait` селектора или значение по умолчанию вызывающего кода.
  Первая альтернатива, у которой есть совпадения, побеждает.
- **Распознавание состояния** — чистая функция `classify_page(probe, policy)`
  над пробником страницы; цикл ожидания (`StateWaiter`) управляет повторами,
  перезагрузками, hook `classify_page_state`, ручным вмешательством и
  «активностью» (две последние — необязательные функции). Маркеры конкретного
  сайта в общие значения по умолчанию не входят: пакет добавляет их в
  `page_state`.
- **Навигация.** `Navigator.navigate(url)`: warmup один раз на сессию, открытие
  с повторами (таймаут считается повреждением страницы, повтора нет), bootstrap
  через hooks пакета один раз на версию за сессию. `Navigator.wait(page_type)` —
  ожидание состояния. Точки fault injection навигации встроены.
- **Код пакета.** `actions.py` определяет `class Actions(ScraperActions)`,
  `pipeline.py` — `class Pipeline(DefaultPipeline)`; без них используются базовые
  классы. Модули пакета импортируются в пространстве имён
  `dailyscraper_packages.<name>`, поэтому относительные импорты внутри пакета
  работают.
- **Hooks.** Состояние сессии доступно hooks через `self`: `page`, `finder`,
  `options` (секция `options` из `scraper.json`), `check_interrupted`. Поэтому
  `collect_list(url)` и `collect_from_input(items)` принимают только данные.
  `discover_pages` появится с задачами discovery на этапе 6.
- **Результат.** Исполнители отдают строки в `ItemSink`; для одиночного запуска —
  NDJSON (`JsonLinesSink`), тот же формат станет partitions на этапе 3.
- **Значения полей.** Текст элемента или атрибут; поле ссылки на detail без
  `attribute` читает `href`; `href` и `src` приводятся к абсолютному URL от
  адреса страницы; `prepare`; затем пробельные символы сжимаются в один пробел,
  а `;`, `<`, `>` удаляются. Отсутствующее поле — `null`, а не строка `"None"`.

## Последствия

- Исполнители страниц не знают о прокси, слотах, очереди и SQLite: на этапе 4
  слот вызывает тот же `DefaultPipeline`.
- Детали по клику (`open_detail_by_click`) пока явно не поддерживаются.
- Временная команда `python -m dailyscraper.app.single` нужна до появления
  полноценного CLI на этапе 8.

# 0021. Проект пользователя: `init`, `new`, запуск из `scrapers.json`

Статус: принято (2026-10-30), заменяет сабмодуль из
[0003](0003-separate-scrapers-repository.md)

## Контекст

Боевые пакеты лежали в отдельной папке, которую фреймворк находил по
абсолютному пути из локальных настроек; команды запускались из папки
фреймворка, а его `config/development/` хранил настройки конкретной машины.
Сабмодуль приватного репозитория в публичном фреймворке раскрыл бы адрес
приватного репозитория в `.gitmodules`, ломал бы `git clone --recursive` у всех,
кроме владельца, и связывал бы фреймворк с чужими пакетами — а связь должна
быть обратной: пакеты используют фреймворк. Пользователю нужен понятный путь:
поставить библиотеку, получить готовую папку проекта, положить туда пакеты и
запускать команды.

## Решение

- **Фреймворк — библиотека, у пользователя — проект.** Проект — папка, из
  которой запускается `dailyscraper`: настройки берутся из её `config/<env>/`,
  пакеты — из `paths.scrapers` (по умолчанию `scrapers/` проекта), данные и
  SQLite — из `paths.data` (`data/`). Ни `main.py`, ни импорта dailyscraper для
  обычной работы не нужно: команда `dailyscraper` ставится вместе с
  библиотекой.
- **`dailyscraper init <папка>`** создаёт проект из шаблона внутри библиотеки:
  `pyproject.toml` с зависимостью на dailyscraper, `config/development/` и
  `config/production/`, `scrapers/` с рабочим примером каталога тестового
  сайта, `.env.example`, `.gitignore`, `README.md`. По умолчанию проект
  зависит от выпуска на PyPI начиная с версии, которая его создала
  (`dailyscraper>=X`); `--framework <папка>` — от локальной копии
  (`editable`), `--branch <ветка>` — от ветки публичного репозитория. Первый
  запуск без установки: `uvx dailyscraper init <папка>`.
- **`dailyscraper new <имя> --template <шаблон>`** создаёт пакет в
  `paths.scrapers` проекта: `scraper.json` и `actions.py`, где уже есть класс
  `Actions` с местами для хуков и подсказками. Шаблоны — файлы внутри
  библиотеки; CLI и будущий веб-интерфейс вызывают одну функцию создания.
- **Запуск из `scrapers.json`.** `dailyscraper run` без имён запускает все
  парсеры из `scrapers.json`, кроме `"enabled": false`; `--group <имя>` —
  группу из `"groups"`; имена в команде, как раньше, запускают только их.
- **Свои пакеты владельца** — такой же проект в приватном репозитории; он
  зависит от dailyscraper: при разработке — путём к соседней папке
  (`editable`), при развёртывании — выпуском с PyPI. Точная
  версия фреймворка записана в `uv.lock` проекта.

## Последствия

- Публичный репозиторий ничего не знает о приватных пакетах; в его `config/`
  остаются только настройки разработки фреймворка и тестов.
- Готовый пакет из будущего магазина кладётся папкой в `scrapers/` проекта.
- Режим браузера для отдельного парсера в `scrapers.json` ждёт режима `shared`
  ([0022](0022-transports-execution-and-hook-skeleton.md)): слот браузера сейчас
  общий для пары «сайт + прокси», и парсеры одного сайта с разными режимами
  делили бы один профиль.

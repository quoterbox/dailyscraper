# 0022. Транспорт, исполнение и скелет хуков

Статус: принято (2026-10-30), уточняет [0009](0009-scraper-actions-hooks.md),
[0012](0012-transports-isolation-and-sync-core.md) и
[0013](0013-scaling-and-replaceable-backends.md); реализуется на этапе 4a

## Контекст

Боевые сайты смешивают способы получения данных: каталог через браузер и
перехваченный запрос к API сайта; каталог через API, размеры через ещё один
запрос, детали — из JSON, встроенного в HTML карточки, наличие — POST-запросом;
одна позиция даёт несколько строк. Фреймворк при этом позиционируется как
простой для обычного пользователя и способный на сложный парсер. Для HTTP
асинхронность естественна (сотни лёгких запросов в одном процессе), для
браузера — нет (память и процессор уходят на процессы Chromium, а не на
ожидание в Python).

## Решение

- **Две независимые оси.**
  - *Транспорт* задаёт пакет (`scraper.json` → `transport`): `browser` или
    `http`. Это свойство сайта.
  - *Исполнение* задают настройки машины и запуска: для браузера —
    `persistent` (свой Chromium и постоянный профиль на пару «сайт + прокси»),
    `ephemeral` (свой Chromium, cookies между запусками через `storage_state`),
    `shared` (один Chromium на машину, у каждой сессии свой контекст и своя
    прокси через CDP); для HTTP — асинхронные дорожки. Один и тот же пакет
    работает в любом режиме своего транспорта.
- **Асинхронность — только в HTTP-слоте.** HTTP-слот — процесс с циклом
  asyncio, дорожки — задачи со своей прокси (вместо потоков «до замеров» из
  0013). Браузерный код остаётся синхронным и в одной версии; экономию памяти
  даёт `shared`, при многих контекстах — потоки внутри слота, по замерам.
  Диспетчер, хранилище и протокол слотов не меняются.
- **Простой JSON.** `scraper.json` остаётся таким, как у браузерных пакетов:
  сайт, ссылки, транспорт, страницы каталога и деталей с селекторами (они
  работают и в браузере, и по HTML без браузера), пагинация, паузы,
  discovery, проверка здоровья, `options`. Простой сайт делается без кода.
- **Скелет хуков на Python.** Фреймворк ведёт цикл (ссылки, страницы, диапазоны,
  повторы, discovery, сохранение после каждой страницы, прокси, капча), пакет
  переопределяет только нужные места:
  - `prepare_session()` — подготовка сессии (регион, вход, перехват API);
  - `page_items(link, page)` — товары одной страницы каталога; `None` —
    прочитать её по селекторам, `[]` — страница пустая;
  - `item_rows(item)` — строки результата одного товара: детали, обогащение,
    разложение по размерам;
  - `input_rows(row)` — строки результата одной входной строки;
  - прежние тонкие хуки (`classify_page_state`, `item_key`, `prepare_output` …).

  Discovery ищет последнюю страницу через тот же `page_items`. Методы могут быть
  обычными или `async def`. Они заменят `collect_list` и `collect_from_input`;
  пакеты WB переписываются на `page_items`.
- **Инструменты в хуках:** `self.http` (запросы с прокси сессии, повторами,
  тайм-аутами и общими с браузером cookies), `self.page` (браузер),
  `self.captured` (перехваченные запросы страницы), `self.extract` (селекторы
  по HTML-строке, встроенный JSON: `__NEXT_DATA__`, `__NUXT_DATA__`,
  `window.*`, JSON-LD, парные скобки), `self.options`, `PageError`.
- **Шаблоны пакетов** для `dailyscraper new`
  ([0021](0021-user-projects-and-scaffolding.md)): `browser`, `http-html`,
  `http-api`, `hybrid`.

## Отклонённый вариант

Описывать в `scraper.json` цепочку шагов (источник, извлечение, куда положить,
пагинация каждого шага). Покрывает много случаев без кода, но конфиг
превращается в самодельный язык программирования, сложный для обычного
пользователя, а нестандартный сайт всё равно требует кода. Простой JSON и
скелет хуков дают тот же охват, а сложное остаётся обычным Python.

## Последствия

- Перед кодом этапа 4a — таблица по всем живым парсерам (браузерным и HTTP):
  шаги, источники, извлечение, пагинация, строк на позицию, авторизация,
  cookies; набор методов скелета и инструментов проверяется по ней.
- Тестовый сайт получает JSON API, POST-каталог и страницу со встроенным JSON —
  каждый вид источника проверяется приёмочным тестом.
- Документация по хукам собирается из docstring'ов `ScraperActions`.

# 0017. Прокси: пул, здоровье, выбор и изоляция сессий

Статус: принято (2026-10-28), уточняет [0012](0012-transports-isolation-and-sync-core.md)
и [0016](0016-session-limits.md)

## Контекст

Перенос прокси из MVP: источники static/gateway/api, network check, circuit
breaker, MV3-расширение и профили. В MVP здоровье жило в памяти одного run,
идентичность API-прокси была позиционной (`api_001`), а сессия gateway
задавалась солью из переменной окружения.

## Решение

- **Пул.** `proxies.json` — схема v2 MVP с источником `none` (по умолчанию,
  прямое подключение), `static`, `gateway`, `api`. У каждой прокси стабильный
  `ProxyId`: имя из списка, шаблон имени сессии gateway (`res_01`…), поле имени
  из ответа API. `scrapers.json` может ограничить парсер списком `proxy_names`.
- **Сессии gateway.** Идентификатор сессии в логине включает `generation`
  (`session_id_template`, по умолчанию `{salt}{index:02d}g{generation}`):
  новая генерация — новый выходной IP под тем же `ProxyId`. Шаблон без
  `{generation}` — ошибка настроек.
- **Здоровье** — circuit breaker MVP по паре `(site, ProxyId)`, состояние в
  общем хранилище (`proxy_health`), изменение — атомарно. Блок, капча, 407
  открывают сразу; тайм-ауты, сетевые ошибки, пустые и упавшие страницы — после
  `consecutive_failures_to_open` подряд. Статичная прокси отдыхает растущий
  cooldown, затем пробуется снова (half-open); вращаемая сессия gateway вместо
  отдыха получает новую генерацию.
- **Выбор прокси** — `ProxyAllocator`: открытые пропускаются, остальные по
  порядку healthy → unknown → degraded → half-open, внутри — по порядку пула;
  прокси, на которых задача уже упала (`avoid`), обходятся, пока есть другие.
  `BrowserManager` берёт первую прокси, на которой сессия укладывается во все
  лимиты ([0016](0016-session-limits.md)).
- **Отчёт о сессии.** После каждой попытки диспетчер сообщает здоровью итог
  (категорию ошибки или успех); при открытии circuit слот этой прокси
  закрывается, повтор задачи избегает прокси.
- **Network check** перед запуском: HTTP-запрос через каждую прокси
  (`proxy_check`); не прошедшая проверку прокси открывается для всех сайтов
  запуска.
- **Режимы изоляции** ([0012](0012-transports-isolation-and-sync-core.md)):
  - `ephemeral` (по умолчанию) — браузер без профиля, прокси с авторизацией
    Playwright на уровне запуска;
  - `persistent` — профиль `profiles/<site>/<ProxyId>`, авторизация через
    MV3-расширение; до первой навигации проверяется, что расширение применило
    прокси, иначе запуск сессии падает. Профиль очищается, когда меняется
    идентичность прокси (адрес, учётные данные, генерация). В headless используется
    полный Chromium: headless shell и брендированный Chrome расширения не
    загружают. Режим добавляет лимит `(site, proxy) = 1`.
- **Блокировка ресурсов** — изображения, медиа и шрифты по умолчанию; документ
  не блокируется никогда.
- **Ротация сессии слота** — по `slot_max_tasks` и `slot_max_age_seconds`.

## Последствия

- Соседний запуск видит открытый circuit сразу, без своей проверки.
- Конфиги MVP переносятся почти без изменений; отличия — `{generation}` в
  шаблоне сессии gateway и `fallback_to_static` вместо `fallback` у API.
- Пороги блокировки запуска (`min_healthy_*`) — правила ворот этапа 6.

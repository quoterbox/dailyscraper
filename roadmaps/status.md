## Текущий этап: 7 — боевые пакеты, браузерная часть

Код и тесты готовы, ожидают коммита владельцем; нужен пробный прогон на живых
сайтах.

### Сделано

- Шесть браузерных пакетов MVP перенесены в отдельный приватный репозиторий
  пакетов (`paths.scrapers` в локальных настройках): четыре каталога одного
  маркетплейса с общей подготовкой сессии (пункт выдачи), ожиданием каталога и
  артикулом из ссылки, два пакета второго маркетплейса со сбором через API
  сайта — каталог и вход по артикулам. Общий код пакетов — в `common/` рядом с
  ними; у пакетов свои тесты.
- Контракт хуков для таких пакетов — ADR
  [0020](decisions/0020-live-packages-and-hook-contract.md): `PageError` с
  категорией, `open_page`, `collect_list(url, pages)` после открытия ссылки,
  `collect_from_input(row)` по одной строке для пакета без страницы деталей
  (все строки результата под номером входной строки и номером части),
  `discover_last_page(url, start, limit)`, `run_warnings()` в итогах run.
- Капча во время подготовки сессии ждёт человека (`probe_bootstrap_state`) и
  подготовка продолжается; не решённая подготовка пробуется снова.
- Discovery вызывает `after_first_open` для открытых страниц; шаблон адреса
  страниц нужен ему только тогда, когда ищет фреймворк.
- `scraper.local.json` поверх `scraper.json` для пробных прогонов (сделан для
  пакетов из локальных настроек MVP: пара ссылок, `last_page` 2–5).

### Проверено

| Команда | Результат |
|---|---|
| `uv run python tools/test_suite.py fast` | 389 passed |
| `uv run python tools/test_suite.py browser` | 11 passed, тестовый сайт через новый порядок хуков |
| `uv run ruff check .`, `uv run ruff format --check .` | чисто |
| тесты репозитория пакетов | 25 passed |

Живые сайты в автоматических тестах не открываются.

### Осталось на этапе 7

- Пробный прогон владельцем каждого пакета с `scraper.local.json`, затем
  полный; парный прогон со старыми парсерами и сравнение строк (критерий плана).
- Вход из xlsx — пока CSV.
- Сброс подготовки сессии из хука, когда место доставки сбилось после неё.
- Около двенадцати HTTP-сайтов — после этапа 4a.

## Этап 6: ворота, discovery, probe, повторы страниц

Закоммичен — ADR [0019](decisions/0019-gates-discovery-and-probe.md).

### Не входит в этап 6

- Восстановление ворот и discovery при resume — этап 8.
- Кэш discovery между запусками (`cache_ttl_hours` MVP) — по потребности.
- Сохранение страниц поиска для пакетов со страницей деталей: нужны задачи
  деталей по элементам списка, а не по строкам входа.
- Дубли между задачами (страница за концом каталога в задаче `[N, 0]`):
  итоговая сборка без строк с одинаковым ключом товара — отдельным шагом.

### Этап 4b: не вошло

- Досылка неотправленных уведомлений упавших run и очистка outbox — этап 8
  (восстановление, retention).
- Удалённое решение капчи (VNC, скриншот в сообщении) и другие мессенджеры —
  по потребности.

### Этап 5: не вошло

- Пороги блокировки запуска по доле здоровых прокси и пробный прогон парсера —
  этап 6 (ворота).
- Ротация сессии gateway по времени — сейчас TTL сессии задаёт провайдер в
  шаблоне логина (`_ttl_30m`), генерация меняется при открытии circuit.
- Из профилей MVP не перенесены: чистка только кэша профиля (`Cache`,
  `Code Cache`, `GPUCache` и др.) по возрасту и размеру с сохранением cookies;
  сброс профиля при смене канала браузера или способа авторизации прокси —
  перенести отдельным шагом (отметка о прогреве сделана на этапе 6).

## Решения после этапа 2

- ADR [0012](decisions/0012-transports-isolation-and-sync-core.md): транспорт за
  узким интерфейсом (Playwright и HTTP), HTTP-транспорт — этап 4a, режимы
  изоляции браузера `persistent` / `ephemeral` / `shared`, синхронное ядро и
  async-фасад для встраивания.
- ADR [0013](decisions/0013-scaling-and-replaceable-backends.md): дорожки
  HTTP-слота, `max_parallel` парсера, пакетные отметки, нагрузочные тесты;
  хранилище за интерфейсами с контрактными тестами (PostgreSQL, Redis, S3 —
  адаптерами), сериализуемый протокол слота, идемпотентность, `host_id`;
  координатор и агенты хостов — этап 10.
- ADR [0014](decisions/0014-captcha-solvers-and-ai-observer.md): ручное решение
  капчи с уведомлением на почту и в Telegram — этап 4b; автоматические решатели
  (сервисы, ИИ) — этап 6a в той же цепочке; ИИ-наблюдатель вне ядра с
  проверяемыми предложениями изменений `scraper.json` — этап 9.
- ADR [0015](decisions/0015-open-core-resources-and-runs.md): ядро — открытая
  библиотека с CLI; HTTP API и веб-интерфейс — поверх `app/`, вне ядра;
  ресурсный профиль 10–15 сайтов на 8 ГБ и 2 ядрах; история запусков,
  `item_key`, версия пакета — хэш; доставка через адаптеры получателей;
  `project_id`; Docker-образ и шаблон развёртывания — этап 8.
- Ближайшая цель — работающий сервис для одного владельца на одной машине
  (этапы 3–7).

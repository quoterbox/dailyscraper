## Текущий этап: 4b — ручная капча и уведомления

Готово, ожидает коммита владельцем.

### Сделано

- `execution/interventions.py`: `ManualIntervention` из MVP в точке
  вмешательства `StateWaiter`. При капче страница не перезагружается, живой DOM
  проверяется до `timeout_seconds`. Решено — `ready` (или дважды подряд `empty` /
  `not_found`), не решено — `captcha` с причиной `manual_intervention_timeout`,
  дальше circuit прокси и повтор. Ожидание только в видимом браузере
  (`--headed`), иначе — `allow_headless`; окно со страницей выводится вперёд.
- Протокол слота: `InterventionStarted` / `InterventionEnded` (`resolved`,
  `timeout`, `aborted`). Состояние слота `waiting`: сторож не считает его
  зависанием, время ожидания не входит в срок задачи, ожидание дольше таймаута с
  запасом — зависание. События `intervention.required/resolved/timeout/aborted`,
  `run.stopping`; в итогах run — счётчики вмешательств по парсерам.
- `observability/notifications/`: перенос `notifications/` MVP. `Notifier` в
  родительском процессе читает события run после курсора, `router` превращает
  их в сообщения (капча и упавший run — срочно, итог run — обычное, старт и стоп
  выключены), outbox в хранилище (миграция 4, `notifications`,
  `consumer_cursors`) с объединением однотипных сообщений, cooldown, TTL,
  повторами с растущей паузой. Каналы Telegram (`sendMessage` через urllib) и
  почта (SMTP, сообщение на получателя), секреты — по именам переменных
  окружения, ошибки каналов очищаются от токена и пароля.
- CLI: `dailyscraper notifications test` — тестовое сообщение во все каналы;
  `runs show` показывает уведомления run.
- ADR [0018](decisions/0018-manual-interventions-and-notifications.md).

Интеграционные тесты (`tests/integration/test_interventions.py`) со слотами:
решённая капча продолжает задачу, две капчи одного run дают одно сообщение,
ожидание не съедает срок задачи; нерешённая — задача `captcha`; выключенные
уведомления ничего не шлют.

### Не входит в этап 4b

- Досылка неотправленных уведомлений упавших run и очистка outbox — этап 8
  (восстановление, retention).
- Удалённое решение капчи (VNC, скриншот в сообщении) и другие мессенджеры —
  по потребности.

### Этап 5: не вошло

- Пороги блокировки запуска по доле здоровых прокси и пробный прогон парсера —
  этап 6 (ворота).
- Ротация сессии gateway по времени — сейчас TTL сессии задаёт провайдер в
  шаблоне логина (`_ttl_30m`), генерация меняется при открытии circuit.
- Из профилей MVP не перенесены: чистка только кэша профиля (`Cache`,
  `Code Cache`, `GPUCache` и др.) по возрасту и размеру с сохранением cookies;
  сброс профиля при смене канала браузера или способа авторизации прокси —
  перенести отдельным шагом; отметка о прогреве профиля с TTL — этап 6.

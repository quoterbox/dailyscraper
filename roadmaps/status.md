## Текущий этап: 7 — боевые пакеты, браузерная часть

Код и тесты готовы, ожидают коммита владельцем; нужен пробный прогон на живых
сайтах.

Первая альфа-версия `0.1.0a1` опубликована на PyPI. В `pyproject.toml` —
ссылки на сайт и репозиторий, ключевые слова и классификаторы; README на
английском с пометками о запланированном. Публикация следующих версий по тегу
`v*` из GitHub Actions (Trusted Publishing) подготовлена, но ещё не подключена
на стороне PyPI. Лицензия MIT: шапка в каждом `.py` из `tools/license_header.txt`,
`THIRD_PARTY_LICENSES` собирается из `uv.lock` (`make headers`, `make licenses`).

### Сделано

- Шесть браузерных пакетов MVP перенесены в отдельный приватный проект
  (папка `scrapers/` проекта, зависящего от фреймворка): четыре каталога одного
  маркетплейса с общей подготовкой сессии (пункт выдачи), ожиданием каталога и
  артикулом из ссылки, два пакета второго маркетплейса со сбором через API
  сайта — каталог и вход по артикулам. Каждый пакет самодостаточен: весь его
  код в его папке, общего кода между пакетами нет; тесты репозитория пакетов
  проверяют каждую копию.
- Контракт хуков для таких пакетов — ADR
  [0020](decisions/0020-live-packages-and-hook-contract.md): `PageError` с
  категорией, `open_page`, `collect_list(url, pages)` после открытия ссылки,
  `collect_from_input(row)` по одной строке для пакета без страницы деталей
  (все строки результата под номером входной строки и номером части),
  `discover_last_page(url, start, limit)`, `run_warnings()` в итогах run.
- Капча во время подготовки сессии ждёт человека (`probe_bootstrap_state`) и
  подготовка продолжается; не решённая подготовка пробуется снова.
- Discovery вызывает `after_first_open` для открытых страниц; шаблон адреса
  страниц нужен ему только тогда, когда ищет фреймворк.
- `scraper.local.json` поверх `scraper.json` для пробных прогонов (сделан для
  пакетов из локальных настроек MVP: пара ссылок, `last_page` 2–5).
- Проект пользователя — ADR [0021](decisions/0021-user-projects-and-scaffolding.md):
  `dailyscraper init <папка>` создаёт проект из шаблона внутри библиотеки
  (`pyproject.toml` на dailyscraper, `config/development|production`, пример
  каталога тестового сайта, `.env.example`, `.gitignore`, README);
  `dailyscraper new <имя>` — пакет из шаблона `browser`; `dailyscraper run` без
  имён запускает включённые парсеры `scrapers.json`, `--group` — группу.
  Шаблоны в `dailyscraper/templates/`, общая функция для CLI и будущего веба —
  `app/scaffold.py`. Приватный проект пакетов переведён на эту схему, путь к
  пакетам в настройках фреймворка больше не нужен.
- Модель транспорта и исполнения, простой JSON и скелет хуков для этапа 4a —
  ADR [0022](decisions/0022-transports-execution-and-hook-skeleton.md).
- Прокси для своих сайтов из MVP: `allowed_sites` и `site_locked` у статичных
  прокси — ADR [0017](decisions/0017-proxies.md). Пример всех источников —
  `config/examples/proxies.json` проекта (не читается при запуске), в
  `config/<env>/proxies.json` — `source: none`, настоящие прокси — в
  `proxies.local.json`.
- Первый живой прогон через прокси (2026-11-27) нашёл зависание: задача после
  сбоя уходит на повтор «не на этом прокси», а единственный простаивающий слот
  парсера сидит на этом прокси и держит место. Диспетчер теперь закрывает такой
  слот; «Not starting a slot» пишется в лог один раз на причину, а не на каждом
  опросе.
- Примеры всех конфигов с полным набором параметров — `config/examples/`
  шаблона проекта (9 файлов). Строятся из моделей настроек:
  `uv run python -m tools.config_examples`; тест `test_config_examples.py`
  падает, если примеры отстали от кода.
- Виды страниц вынесены в `pages/kinds/` (list, detail, auth) и их исполнители —
  в `page_scrapers/kinds/` с теми же именами файлов. Описания остаются в слое 1,
  исполнители — в слое 3; импорты пакетов через `dailyscraper.pages` и
  `dailyscraper.page_scrapers` не изменились.

## Этап 6: ворота, discovery, probe, повторы страниц

Закоммичен — ADR [0019](decisions/0019-gates-discovery-and-probe.md).

### Не входит в этап 6

- Восстановление ворот и discovery при resume — этап 8.
- Кэш discovery между запусками (`cache_ttl_hours` MVP) — по потребности.
- Сохранение страниц поиска для пакетов со страницей деталей: нужны задачи
  деталей по элементам списка, а не по строкам входа.
- Дубли между задачами (страница за концом каталога в задаче `[N, 0]`):
  итоговая сборка без строк с одинаковым ключом товара — отдельным шагом.

### Этап 4b: не вошло

- Досылка неотправленных уведомлений упавших run и очистка outbox — этап 8
  (восстановление, retention).
- Удалённое решение капчи (VNC, скриншот в сообщении) и другие мессенджеры —
  по потребности.

### Этап 5: не вошло

- Пороги блокировки запуска по доле здоровых прокси и пробный прогон парсера —
  этап 6 (ворота).
- Ротация сессии gateway по времени — сейчас TTL сессии задаёт провайдер в
  шаблоне логина (`_ttl_30m`), генерация меняется при открытии circuit.
- Из профилей MVP не перенесены: чистка только кэша профиля (`Cache`,
  `Code Cache`, `GPUCache` и др.) по возрасту и размеру с сохранением cookies;
  сброс профиля при смене канала браузера или способа авторизации прокси —
  перенести отдельным шагом (отметка о прогреве сделана на этапе 6).

  `project_id`; Docker-образ и шаблон развёртывания — этап 8.
- Ближайшая цель — работающий сервис для одного владельца на одной машине
  (этапы 3–7).
